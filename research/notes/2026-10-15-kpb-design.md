# Kohane Processing Bundle（KPB）设计稿

> 2026-10-15 起案。本文是「作编混」落点的口径文档：KPB 是什么、里面装什么、怎么封、
> 体积怎么控、要逆向什么、以及怎么算通过。

---

## 1. 定位

KPB = **KID（kohane-index-desuno）的追加能力束**，承载**作编混**（作曲・编曲・混音）。

| 维度 | 口径 |
|---|---|
| 身份 | KID 的 DLC：装上去即生效，卸下来即复原 |
| 分发 | releases 里**单独下载**（`kohane-processing-<version>.kpb`） |
| 独立性 | **不可独立使用**：裸包是死物，只有 KID 解得开 |
| 体积 | **kohane 化后 ≈ 源总量的 8%–20%**（源 10 GB → 0.8–2 GB；源 26 GB → 2–5 GB）。上限硬，下限同样是约束 |
| 命名 | 一律 `Kohane Bassline` 一族；束内不出现第三方产品名 |

## 2. 格式族

一切落盘状态用 kohane 自己的容器；后缀即语义。

| 后缀 | 名称 | 承载 | 取代 |
|---|---|---|---|
| `.kpb` | 束 | KPB 本体（封装 + 封存 + 清单） | — |
| `.kbb` | 库 | 一套乐器集合（多预置 + 其采样引用） | `.sf2`、`.fxb` |
| `.kbi` | 器 | **单件音色**（参数 + 采样引用或合成配方） | `.fxp`、单个 sf2 预置 |
| `.kba` | 声 | kohane 的 PCM 音频容器（含编解码档位） | `.wav`、`.aiff`、sf2 内嵌采样 |
| `.kbs` | 谱 | 拍速／调／段落／声部／音符 | 宿主工程语义 |
| `.kbm` | 混 | 通道条、总线、增益／声像／送出、效果链 | 各宿主的混音状态 |
| `.kbw` | 波 | 波形包络与音频描述（可视化与混音共用） | — |
| `.kbv` | 视 | 瀑布布局与配色主题 | MIDIFall 主题贴图 |

## 3. 输入与输出的边界

- **输入（只读）**：`.sf2` / `.flp` / `.fxp` / `.fxb` / `.ffp` / `.wav` / `.aiff` / `.mid`
  —— 一律**读了就转**，kohane 的任何状态都不以它们承载。**`.sf2` 不例外**。
- **输出（导出）**：**MIDI + 常见音频格式**（WAV／FLAC／MP3…）。导出是「给别的工具看的」，
  不是 kohane 的存储。
- **不做**：不渲染 `.flp`（无必要）。

## 4. 封存与校验

- **密钥路径**：沿用引擎既有的 HKDF 派生 + AES-256-GCM 封存，密钥绑定**本安装**；
  换机、无 KID、或仅解包都开不了。
- **失败要说得清**：裸 `.kpb` 的解包失败必须是「缺少 KID 的密钥」，而不是「格式不认识」。
- **能力面**（装好之后 KID 才有的操作）：
  `install`（装入并校验）、`list`（列出束与版本）、`verify`（完整性 + 体积比例 + 自证）、
  `remove`（卸净，工具面复原）。

## 5. 体积政策（本设计的主战场）

体积不是固定窗口，而是**随源总量走的比例**：两个数据点（源 10 GB → 0.8–2 GB；源 26 GB → 2–5 GB）
都指向 **8%–20%**（1/12.5 ～ 1/5）。上限硬，下限同样是约束——低于比例说明内容缺失，高于比例说明瘦身没做到。

| 资产 | 原始 | 目标 |
|---|---|---|
| SD-90 `.sf2` × 97 | 6.7 GB | 保留**全部预置定义** + 采样**去重、裁循环、必要时重采样** → 0.8–1.2 GB |
| Sylenth1 `.fxp` / `.fxb` | ~60 MB | 参数化 → 10–20 MB |
| FabFilter `.ffp` | 小 | 参数化 → 几 MB |
| 合成核心 + 逆向参数表 | — | < 5 MB |
| 谱／混／视（单曲） | — | < 1 MB |

三条约束：

1. **`.kba` 自带编解码阶梯**：`adpcm`（**默认**）→ `lossless`（可选）→ `raw`（兜底）。
   档位是控制体积的主要旋钮。
2. **采样先去重再入库**：同一波形常被多个键区／力度层共用；先去重、再裁循环点，
   通常能省下一半以上。
3. **体积纳入校验**：`verify` 报告体积与其**源总量之比**并判定——**低于 8% 视为内容缺失，
   高于 20% 视为瘦身未达标**，两者都算不通过。

## 6. 逆向清单

1. **FL 原生音源**：`plugin_blob` / `channel_blob` 里的参数块 → **参数映射**（哪个字节是哪个旋钮），
   据此让 kohane 自己**合成**出对应音色，而不是搬运采样。
2. **FL Studio 本身**：`mixer_blob`、通道级效果、总线与主链的**信号流**——「混」要对齐的部分。
3. **外部插件**（Nexus／Kontakt／Serum／Heavier7Strings／EDIROL／SpaceCraft／FabFilter）：
   **只记录参数与引用，不复制其音色**。它们的音色重现不在本束职责内。
4. **范围口径**：先做 **A（一首曲子里实际用到的原生音源）**，闭环跑通后再谈全量。

## 7. 瘦身思路（参考注册机音乐）

- **合成优于堆样本**：几十 KB 能装下整首曲子的年代，靠的就是单周期波形 + 参数化包络 + 极省的效果链。
- **播放器与数据分离**：小引擎（kohane 合成核心）+ 小数据（`.kbi` 几百字节级）。
- **字节级的音色描述**：参数按需要精度存，不按宿主状态块原样存。

## 8. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| 1 | 设计稿 + 格式表 + 封存／校验口径 | 本文可复核 |
| 2 | KID 侧 KPB 面：`install / list / verify / remove` | 无 KID 开不了；装上工具面增加；卸净复原 |
| 3 | 作曲器与瀑布可视化进束（`.kbs` / `.kbv` + `.kbw`） | 束内自证：谱能重放，波形能画 |
| 4 | 「混」：分轨渲染 + 增益／声像／总线处理，逐轨并行 | 导出的音频与 `.kbm` 一致；多核有实测加速 |
| 5 | 体积达标与素材转换（sf2 → `.kbb`/`.kba`） | **束体积 / 源总量 ∈ [8%, 20%]**，且内容可枚举 |

## 9. 验收清单（可逐条核对）

- [ ] 裸 `.kpb` 在 KID 之外解不开，且失败原因是「缺密钥」
- [ ] `install` 后 KID 工具面增加作编混一组；`remove` 后复原
- [ ] 束内**无第三方容器**承载产品语义（含 `.sf2`）
- [ ] 导出覆盖 MIDI + WAV／FLAC／MP3；**不导出** `.flp`
- [ ] 束体积与源总量之比落在 8%–20%；`verify` 会因越界而**不通过**
- [ ] 只凭 kohane 文件即可枚举每件乐器的采样、键位范围与循环点
- [ ] 分轨渲染有并行实测（常驻池）
