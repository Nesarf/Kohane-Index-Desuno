# KID 的专用依赖层

本目录是 KID **自己的**依赖账本。规则很短：

1. **引擎内核是纯 Node。** 标准库之外要用的一切，都要在 `manifest.json` 里登记。
2. **零「未登记」依赖。** 运行时不得依赖任何没写进清单的东西。
3. **每条都要有身份**：`id`、`kind`、来源、许可、字节数、`sha256`、以及「谁在用它」。
4. **哈希不符即失败**，不是警告——要么把文件复原，要么**有意识地**更新条目。
5. **不在运行时下载**：依赖由一次显式的、记录在案的步骤获取，绝不作为副作用悄悄拉取。

## 为什么要有这一层

引擎原先的纪律是「零依赖」，这条在核心上继续成立；但「解码压缩音频」「播放」这类能力
**本质上需要外部实现**。把这类实现要么散落在机器上、要么藏在安装脚本里，都会让
「KID 到底依赖了什么」变成一个说不清的问题。所以改成：**依赖是我们的，也是可见的。**

## 条目形态

| 字段 | 含义 |
|---|---|
| `id` | KID 内部用它 |
| `kind` | `library` / `decoder` / `analyzer` / `binary` / `data` |
| `name` | 实际的名字（可以带厂商名：这是内部账本，不是产品输出） |
| `origin` | 从哪来（registry / 某个来源 / 本机构建） |
| `licence` | 许可，必须写 |
| `file` + `sha256` + `bytes` | 随包发布的文件才需要；由包管理器装的库按锁定版本，`file` 为 `null` |
| `purpose` / `usedBy` | 它为什么在、谁在用它——没有用途的依赖应当删掉 |
| `planned` 段 | 已决定要加、但还没选定的实现（例如压缩音频的解码器） |

## 谁来守着它

`tools/check-deps.mjs`：清单能解析、每条都声明了许可与用途、随包文件的存在且哈希相符、
并且**引擎的 import 里没有清单之外的裸模块名**。它随「五道不变量」一起跑。
